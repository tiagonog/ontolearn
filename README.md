# OntoLearn: A Formal Ontology for Competency-Based Learning Analytics

Research artifacts for two papers by the same authors (CIn/UFPE):

1. **"OntoLearn: A Formal Ontology for Competency-Based Learning Analytics and Semantic Modeling"** — SBIE 2026, pp. 44–56, [doi:10.5753/sbie.2026.25639](https://doi.org/10.5753/sbie.2026.25639). Introduces the ontology (**v1.0**, file `ontology/ontolearn.owl`).
2. **"Closing the Report–Artifact Gap in an Ontology for Competency-Based Learning Analytics"** — submitted. Audits v1.0 against its published description and releases the completed **v2.0** (`ontology/ontolearn-v2.owl`) together with the scripts that reproduce every reported measurement.

OntoLearn is an OWL 2 DL domain ontology for modeling the Knowledge, Skills, and Attitudes (KSA/CHA) triad, proficiency levels, and prerequisite chains in competency-based Learning Analytics.

Base namespace: `http://www.ontolearn.com/ontologia#`

## Errata for v1.0 and the SBIE 2026 description

The audit paper re-derived every structural claim directly from `ontology/ontolearn.owl`. Four statements in the SBIE 2026 paper and in earlier revisions of this README are **not supported by that file**. They are listed here so that the public record is self-correcting; the file itself is left unmodified, because it is the artifact the published paper describes.

| Claim | Measured in `ontolearn.owl` |
|---|---|
| DL expressivity `ALCHIF(D)` | **`SIF(D)`**. The file contains no `rdfs:subPropertyOf` axiom, so the `H` is unrealized; and transitive roles require `S`, not `ALC`. (v2.0 does reach `SHIF(D)`.) |
| "KSA disjointness is enforced pairwise" | **Absent.** The file declares exactly two `owl:disjointWith` axioms — `Aprendiz ⊥ Instrutor` and `Competencia ⊥ RecursoDeAprendizagem`. Neither involves Knowledge, Skill, or Attitude. Added in v2.0 (family F2). |
| `Assessment ⊑ ∃evaluatesCompetency.Competency`; qualified cardinality; `hasScoreValue` | **Absent.** Zero `owl:Restriction`, zero cardinality axioms, and no score-valued data property in any version. Existential constraints added in v2.0 (family F3). |
| ABox of 32 (v6) / 40 (v10) individuals | **16 and 20**, by two independent counting criteria. |

Two latent defects were also found in v1.0 and repaired in v2.0: the class `Subjetiva` carries no `rdfs:subClassOf` link to `Questao`, which silences one third of question instances under subsumption queries; and the union domain of `:descricao` omits `NiveisDeProficiencia`, which the ABox nevertheless uses.

### SPARQL errata

`sparql/cq4.rq` is preserved as deposited. Executed against `ontology/ontolearn.owl` it returns the **empty set**: it binds the target competency through `rdfs:label`, which in this ontology is populated on classes and properties but on no competency individual. Competency names are held in the data property `:nome`. The working form is:

```sparql
PREFIX : <http://www.ontolearn.com/ontologia#>

SELECT ?preReq ?nome WHERE {
  ?comp :nome "Herança em Python" .
  ?comp :requer+ ?preReq .
  ?preReq :nome ?nome .
}
```

Note that even in this corrected form the query returns a single prerequisite, because the shipped ABox contains one `:requer` edge — so the transitive operator has nothing further to traverse.

## Reproducing the audit (v2.0)

```bash
pip3 install rdflib==7.6.0 owlrl==7.6.2 owlready2    # plus a Java runtime for HermiT

python3 scripts/build_v2.py ontology/ontolearn.owl ontolearn-v2.ttl ontolearn-v2.owl
python3 scripts/ablation.py ontology/ontolearn.owl
python3 scripts/scalability_regimes.py
python3 scripts/multirun.py 5
```

Counts are deterministic under seed 42 and reproduce exactly; timings vary by machine. Expected key values: `v2.0 − F0` is the only inconsistent configuration; OWL-RL materialization yields **834** domain-relevant entailed triples for v1.0 and **919** for v2.0.

## Version evolution

| Metric | v0 | v2 | v6 (post-OOPS!) | v10 = v1.0 | v2.0 |
|---|---|---|---|---|---|
| Classes | 82 | 50 | 28 | 29 | 29 |
| Object properties | 18 | 26 | 48 | 48 | 50 |
| Data properties | 0 | 0 | 27 | 27 | 27 |
| Inverse properties | 0 | 4 | 24 | 24 | 25 |
| Transitive properties | 0 | 1 | 2 | 2 | 2 |
| Sub-property axioms | 0 | 0 | 0 | 0 | 6 |
| Disjointness axioms | 0 | 0 | 2 | 2 | 7 |
| Individuals (synthetic ABox) | 0 | 0 | 16 | 20 | 20 |

Twelve intermediate files were preserved during development; content hashing reduces them to ten distinct states (two pairs are byte-identical). v0 enumerated entire knowledge domains and ISCED education levels as classes; successive OOPS! cycles (pitfalls P04, P08, P11, P13, P20, P41) replaced that enumerative taxonomy with a leaner relational core. No state in the lineage ever contained a sub-property axiom, a class restriction, or a cardinality constraint — those families were not lost in refactoring, they were never introduced.

## Key modeling notes

- `:requer` (Competencia → Competencia) is declared `owl:TransitiveProperty`; `:ehRequeridaPor` is its declared inverse (also transitive). In the SBIE paper, `:ehRequeridaPor` is presented as *isPrerequisiteOf* for readability.
- The ABox contains only **synthetic instances** generated from the schema's constraints. No real student data is included.
- v2.0 retains the legacy IRI for artifact continuity.
